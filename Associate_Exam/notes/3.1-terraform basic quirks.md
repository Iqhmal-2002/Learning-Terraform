# Setting up multi cloud provider
Only need 1 required_provider, alias is only needed if you're referring to the same cloud but with different config like a different region

terraform {
  required_providers {
    azurerm = {
      source  = "hashicorp/azurerm"
      version = "=5.0.0"
    }
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

To connect to aws, use aws configure instead of aws sso
aws sso would need PAYG, aws configure can work with the free version

# Editing config during a running apply
apply snapshots the .tf files at the start (parse -> plan -> "yes" -> execute)
Editing/saving .tf mid-apply does nothing to the running apply, only applies on the next plan/apply
Exception: scripts run during apply (local-exec "bash ./setup.sh") are read when they run, so edits can leak in
file() / templatefile() are read at plan time, so they're part of the snapshot

Can't start a second apply to "fix it", the running one holds the state lock (HCP queues it instead)

Stopping:
1st Ctrl+C = graceful, finishes in-flight resources and saves state
2nd Ctrl+C = hard kill, can leave resources created but not in state

Next plan after an interrupted apply = current config vs current state
- already created, untouched -> no change
- attribute changed -> update in place, or replace if provider says "forces replacement" (provider decides, not me)
- address renamed -> destroy + create, unless a moved block -> just moved
- failed mid-create -> tainted -> replace
- never created -> create
